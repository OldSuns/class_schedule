# 实施计划

## 1. 事件工具与测试先行

1. 新增最小事件规范化、时间解析、按周/日/组查询和冲突判定工具。
2. 先写 Node 单元测试：完整事件 schema（含独立 `teacher` / `note`）的拒绝路径、时间有效性、共同课程、1–7 组筛选、2026-07-13 周起点、7 周 × 7 组完整轮转矩阵、全部共同事件的日期/时间/地点及数据不含联系人字段。
3. 将旧的硬编码 ABCD/6A/6B/7C/7D 组别逻辑替换为单一 1–7 组实现。

验证：`npm run test:unit`。

## 2. 数据与持久化

1. 从 `research/excel-sources.md` 建立暑期事件数据，确保所有共同课和 7 组轮转均有来源。
2. 将课表状态、远端更新、签名、导出 JSON 和小组件快照迁移到事件格式；导出 `schedule-v2.json` 当前载荷及由同一源生成的 `schedule.json` v1 兼容投影。
3. 实现设计文档列出的全部夏季存储键、三个固定 `@summer-schedule` 远端 URL、基于已校验 `updatedAt` 的并发选择顺序和重置契约；测试预置旧本地缓存、旧远端快照、旧数组载荷、错误 `version`/`updatedAt`/学期起点、网络/格式失败和重置后均不能恢复旧课程或请求 `main`。
4. 覆盖安装恢复状态时，以 `Date.parse` 后的绝对时间戳比较双方 `updatedAt`，仅保留严格晚于内置课表的远端快照；内置课表相同或更新时清除陈旧远端状态并切回内置来源，手动课表不受影响。回归矩阵覆盖手动课表、严格更新的远端、同一时刻不同偏移和更旧远端，并断言最终来源与陈旧状态清理结果。

验证：事件数据测试、导出脚本、`npm run test:unit`。

## 3. 真实时间 UI

1. 将固定节次表格替换为真实时间视图，支持周次、周内日期、右上角唯一的 1–7 组入口，并以统一“时间 / 课程 / 地点”日表展示当天全部事件；上午见习与下午共同课程不得使用两套布局。
2. 将当前课程进度从标题栏移到主内容日表上方，并用事件时段驱动课程名、地点、进度和对应行焦点；不新增“精确时段”徽标或按课程类型猜测的分区标题。
3. 用事件时段重写课程详情底部弹层；弹层展示真实时间、地点、教师、适用对象和编辑/删除操作，背景复用当前时间轴页面，编辑器改用原生时间输入。
4. 根据 Pencil 稿和当前 `Header` / `SettingsMenu` 结构更新标题栏、12–16px 纵向节奏、底部导航及设置页；移除选修、A–D 和显示模式，主题改为直接的 M3/简约蓝双选项并将默认设为简约蓝；演示态展开 4×2 组别网格。

验证：新增服务端渲染测试覆盖关键标签、1–7 组选项和精确时间；`npm run test:unit`。

## 4. 通知、小组件与完整校验

1. 让 Web 通知计划、Android 小组件和当前课程均以事件时间为准，并为共同课程、已选组、重叠事件、晚间课程和相同开始时间的合并通知写契约测试。
2. 为小组件事件快照写纯 JS 序列化测试，再运行 Android 构建或相关 Gradle 编译检查，检查快照字段与 Java 端的同步。
3. 检查远端课表更新、重置内置课表和旧缓存隔离。

验证顺序：`npm run test:unit` → `npm run build` → Android 相关构建/静态检查 → 人工确认 Pencil 对照的移动端主流程。

## 5. 日期手势、组别选择器与主题隔离

1. 先为 `getAdjacentWorkday({ week, day }, direction)` 写失败测试，覆盖右滑前一天、左滑后一天、周一/周五连续跨周和第 1/8 周停止；再实现纯函数，并由 `App` 的单一 handler 在同一事件中更新周次和日期。周切换箭头与设置页快速选周继续保留当前日期。
2. 先扩展 SSR 测试，要求组别触发器不再渲染原生 `select`，具有稳定胶囊按钮、listbox 展开语义和 4+3 组选项；再用现有 React/Tailwind 实现无头浮层，补齐外部点击与 Escape 关闭。
3. 恢复旧版已验证的 `useWeekSwipe` move-phase 手势处理，将左右回调改为前后工作日；保留横纵轴锁定、阈值、`preventDefault()`、点击抑制与 `touch-action: pan-y`。保留现有日期按钮及周切换按钮作为可访问的非手势入口。
4. 使用 Motion animation controls 为日期变化增加约 180ms 的方向性位移淡入；动画方向由完整周次和工作日顺序计算，并尊重 reduced-motion。
5. 先更新主题契约测试，要求暑期独立存储键与简约蓝默认值；再修改主题持久化，旧通用主题键不迁移。
6. 功能与构建验证通过后，运行版本同步脚本，将 `package-lock.json` 根版本与 `packages[""]`、Web 常量及 Android 元数据统一更新为 `2.1.1`。

验证：目标单测红—绿 → `npm run test:unit` → `npm run build` → 版本一致性检查 → `git diff --check`。

## Review gates

- 每一阶段后检查是否重新引入固定节次作为时间来源、ABCD 组别、旧课表缓存或联系人电话号码。
- 最终审查全部变更，确认输入校验、无静默回退、无重复受众逻辑、旧缓存不能恢复、时间轴可扩展不裁切，且资料来源可追溯。

## 6. 启动更新检查

1. 复用现有 Release 检查器和平台下载页打开逻辑，新增全局更新弹窗。
2. 启动时按本地自然日检查一次，网络错误静默并采用 3 分钟重试冷却；合并 Strict Mode 的并发启动检查。
3. 保留设置页手动检查入口，确认暑期版本保持为 `2.1.1`。

验证：目标单测 → `npm run test:unit` → `npm run build` → `git diff --check`。
